# Marketing Tools

Веб-приложение для маркетинговой аналитики: собирает данные из **Bitrix24**, **Яндекс.Метрики** и **Яндекс.Директа**, делает SEO-аудит сайтов и даёт их анализировать через **OpenAI** — всё в одном экране: живой дашборд слева, AI-чат с доступом к актуальным данным справа.

## Что внутри

- **Дашборд в реальном времени** — KPI по лидам/сделкам (Bitrix24), рекламным кампаниям (Директ) и трафику (Метрика) по каждому сайту отдельно, с автообновлением.
- **Мульти-сайтовость** — один аккаунт Bitrix24/Директа может обслуживать несколько сайтов; у каждого сайта свой счётчик Метрики, свой список страниц для аудита и свой набор источников CRM (сопоставляется вручную).
- **SEO-аудит сайта**: коды ответа страниц (битые ссылки), базовые SEO-поля (title/description/h1), эвристики UX (формы, CTA, alt, viewport), каннибализация контента (с фильтрацией общих для всех страниц шаблонных слов — шапка/меню/футер не считаются "похожестью"), скорость через Google PageSpeed Insights, сравнение с конкурентами.
- **Детальный дашборд по сайту** — клик «Подробнее» открывает полную картину: визиты по дням, источники трафика, топ страниц, воронка сделок, цели Метрики (конверсии на сайте), проблемные страницы, топ пар каннибализации, скорость.
- **Цели Метрики** — конверсии на сайте (отправка формы, клик по телефону и т.п.) сопоставляются с каждым сайтом отдельно, закрывая разрыв между «зашёл на сайт» и «оставил заявку в CRM».
- **AI-чат** — отдельная панель, где можно в свободной форме спросить про текущие данные («сколько лидов за неделю», «есть ли битые страницы», «как дела у сайта X») и получить ответ, учитывающий весь текущий срез данных по всем источникам.
- **Логин с паролем** — приложение закрыто авторизацией, один администратор на инсталляцию.

## Архитектура

- **Backend**: Node.js (≥22) + Express.
- **Хранилище**: встроенный `node:sqlite` — файл `data/app.db`, без нативной компиляции зависимостей.
- **Frontend**: без сборки — чистый HTML/CSS/JS, Tailwind CSS и Chart.js подключены через CDN.
- **Авторизация**: один администратор, пароль хранится как bcrypt-хеш, сессия — подписанная cookie (`cookie-session`), секрет генерируется один раз и хранится в БД.
- **Интеграции**: собственные клиенты для Bitrix24 REST (webhook), Яндекс.Метрики (Reporting API), Яндекс.Директа (API v5, Reports), Google PageSpeed Insights, OpenAI (Chat Completions, совместимо с любым OpenAI-совместимым прокси через настраиваемый Base URL).

Все внешние вызовы (Bitrix24/Метрика/Директ) объединены в один модуль — `src/liveData.js` — который использует и дашборд, и AI-чат, чтобы не дублировать запросы. Результат кэшируется на 60 секунд: если дашборд и чат обращаются почти одновременно, тяжёлый сбор данных не повторяется.

## Быстрый старт

```bash
git clone <URL вашего репозитория>
cd marketing-tools
npm install
npm start
```

Приложение поднимется на `http://localhost:4100` (порт настраивается переменной окружения `PORT`).

Для продакшена рекомендуется процесс-менеджер (например, [pm2](https://pm2.keymetrics.io/)):

```bash
pm2 start server.js --name marketing-tools
pm2 save
```

Если приложение стоит за HTTPS-реверс-прокси, включите защищённые cookie сессии:

```bash
COOKIE_SECURE=true pm2 start server.js --name marketing-tools
```

## Первый вход и авторизация

При первом запуске приложение ещё не знает логин/пароль — любой переход на `/` отправит на `/setup`, где нужно задать логин и пароль администратора (пароль — не короче 8 символов, хранится как bcrypt-хеш). После этого `/setup` больше не доступна, вход — только через `/login`.

Сменить пароль можно в любой момент в «⚙ Настройки → Смена пароля», указав текущий пароль.

Сессия живёт 30 дней (подписанная httpOnly-cookie), «Выйти» в шапке — обычный logout.

> Для production-инсталляции за HTTPS не забудьте выставить `COOKIE_SECURE=true` (см. выше) — иначе cookie сессии будет уходить и по HTTP.

## Настройка интеграций

Все ключи и токены вводятся в UI («⚙ Настройки»), не в файлах конфигурации — хранятся в SQLite на сервере.

### Bitrix24

1. В Bitrix24: Профиль → Разработчикам → Другое → **Входящий вебхук**, с правами на CRM.
2. Вставьте URL вебхука в настройках.
3. (Опционально) «Загрузить список воронок» — выберите, какие воронки сделок анализировать (по умолчанию — все).

### Яндекс.Метрика

1. Создайте OAuth-приложение на https://oauth.yandex.ru/client/new с правом «Яндекс.Метрика → Статистика».
2. Получите OAuth-токен по ссылке `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ваш Client ID>`.
3. Токен общий для всех счётчиков — вводится один раз в настройках. ID конкретного счётчика указывается отдельно для каждого сайта (раздел «Сайты»).

### Яндекс.Директ

1. Создайте OAuth-приложение с правом «Яндекс.Директ», получите токен так же, как для Метрики.
2. Для обычного (не агентского) кабинета поле `Client-Login` оставьте пустым.
3. **Важно:** для нового OAuth-приложения в Директе нужно один раз подтвердить доступ — `direct.yandex.ru` → Настройки API → вкладка **«Мои заявки»** → «Новая заявка», указать `Client ID` приложения. Без этого API будет отвечать ошибкой `58 Незавершенная регистрация`.

### OpenAI

- API-ключ и модель (по умолчанию `gpt-4o-mini`).
- Base URL можно переопределить — подходит любой OpenAI-совместимый провайдер/прокси (Azure, OpenRouter, локальный сервер и т.п.).

### Google PageSpeed (опционально)

Ключ увеличивает дневной лимит запросов для оценки скорости загрузки страниц; без ключа работает с низкой квотой.

## Сайты и мульти-сайтовость

Bitrix24 и Яндекс.Директ — общие на весь аккаунт, а вот Метрика и SEO-аудит настраиваются **отдельно на каждый сайт** (раздел «⚙ Настройки → Сайты»):

- ID счётчика Яндекс.Метрики;
- список своих страниц (вручную или через `sitemap.xml`) и список конкурентов для сравнения;
- (опционально) список источников Bitrix24 (`SOURCE_ID` лидов/сделок), которые относятся именно к этому сайту — кнопка «Загрузить список источников» подтягивает реальный справочник из вашего Bitrix24. Без этого сопоставления CRM-раздел в детальном дашборде сайта недоступен, но общая сводка по Bitrix24 всё равно показывается;
- (опционально) список целей Яндекс.Метрики для отслеживания конверсий на сайте — кнопка «Загрузить список целей» подтягивает цели выбранного счётчика.

Срез CRM по сайту считается **без дополнительных запросов к Bitrix24** — данные фильтруются на лету из уже полученного общего списка лидов/сделок. Любое изменение сайта или настроек сразу сбрасывает 60-секундный кэш живого снимка, так что дашборд и чат не отдают устаревшие данные.

## AI-чат: как это работает

Каждое сообщение в чате обрабатывается так:

1. Сервер собирает свежий снимок данных по всем источникам и сайтам (тот же механизм, что и у дашборда, с 60-секундным кэшем).
2. Снимок (в сокращённом виде — без полных текстов страниц, с ограничением на количество пар каннибализации) передаётся модели вместе с историей переписки.
3. Модель отвечает, учитывая только реальные данные; если каких-то данных нет (источник не настроен, нет свежего аудита) — явно говорит об этом, а не выдумывает цифры.

На больших объёмах CRM (тысячи сделок) полный цикл «собрать данные + дождаться ответа модели» может занимать больше минуты, поэтому отправка сообщения устроена асинхронно: запрос сразу возвращает идентификатор задачи, а клиент опрашивает её статус — это исключает обрыв соединения по таймауту браузера/прокси на долгих ответах.

> Чат-эндпоинты рассчитаны на провайдеров, которые могут не поддерживать роль `system` в OpenAI API (встречается у части сторонних прокси/character-сервисов) — все данные и инструкции на всякий случай дублируются прямо в сообщении пользователя, так ответ не теряет контекст независимо от провайдера.

## Структура проекта

```
server.js                      точка входа Express, подключение роутов и авторизации
src/
  db.js                        схема SQLite, все обращения к БД (настройки, сайты, история, чат, админ)
  liveData.js                  сборка «живого» снимка данных по всем источникам + кэш на 60с
  middleware/requireAuth.js    защита роутов/страниц сессией
  integrations/
    bitrix24.js                REST-клиент Bitrix24 (сделки, лиды, воронки, источники)
    metrika.js                 Reporting API Яндекс.Метрики
    direct.js                  API v5 Яндекс.Директа (отчёты по кампаниям)
    site.js                    краулер сайта: статусы, SEO-поля, каннибализация, PageSpeed
    openai.js                  вызовы OpenAI (разовый анализ + чат с живыми данными)
  routes/
    auth.js                    setup / login / logout / смена пароля
    settings.js                хранение ключей интеграций
    sites.js                   CRUD по сайтам
    collect.js                 ручной сбор данных по источникам + справочники (воронки/источники)
    dashboard.js               тонкая обёртка над liveData для дашборда
    chat.js                    асинхронный чат (job + polling)
    analyze.js                 разовый анализ сохранённых срезов данных через OpenAI
public/
  index.html, app.js, style.css   основное приложение (дашборд + чат, без вкладок)
  login.html, setup.html          страницы входа и первичной настройки администратора
data/
  app.db                       файл SQLite (в git не попадает)
```

## Известные ограничения

- **Лимит выгрузки Bitrix24** — сделки и лиды за период выгружаются постранично с ограничением 2000 записей на запрос. На больших объёмах (многие тысячи сделок) это может ограничивать точность агрегатов.
- **Каннибализация контента** — эвристика по пересечению слов (title/h1/текст страницы, за вычетом слов-шаблонов, общих почти для всех страниц сайта). Это не замена полноценному SEO-инструменту, а ориентир.
- **Оценка текста на «плагиат» и вовлечённость** — тоже эвристическая (по структуре и признакам), не сверяется с базой антиплагиата.
- **UX-оценка** — по формальным признакам разметки (формы, CTA, alt, viewport), не визуальный анализ.
- **Тепловые карты и Вебвизор Яндекс.Метрики** — не выгружаются через публичный API, нужно смотреть вручную в интерфейсе Метрики.
- **Google PageSpeed** — бесплatная квота без ключа мала, может быстро исчерпываться.
- **Один администратор** — многопользовательского разграничения прав нет, это инструмент для одного ответственного (или общей учётки внутри небольшой команды).

## Безопасность

- Пароль хранится только как bcrypt-хеш (12 раундов), в открытом виде нигде не сохраняется.
- Секрет подписи сессионной cookie генерируется случайно при первом запуске и хранится в БД — не в коде и не в git.
- Все API-ключи интеграций (Bitrix24, Метрика, Директ, OpenAI, PageSpeed) хранятся в локальной SQLite, не в репозитории — `data/*.db` исключён из git (`.gitignore`).
- Эндпоинты `/api/*` (кроме `/api/auth/*` и `/api/health`) требуют авторизованной сессии.
